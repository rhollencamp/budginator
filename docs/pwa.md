# The PWA

`vite-plugin-pwa` generates the manifest and the service worker. The wiring is
in three small files:

- `src/pwaUpdate.ts` — registers the worker and holds the "an update is waiting"
  flag outside React, because registration happens once at startup in
  `main.tsx`, before any component mounts.
- `src/usePwaUpdate.ts` — subscribes the UI to that flag via
  `useSyncExternalStore`.
- `src/App.tsx` — shows the dot on the burger and the update entry in the
  drawer.

## Updates are offered, never forced

`registerType: 'prompt'` means a new worker installs and then _waits_ instead of
taking over. That is deliberate: taking over mid-session reloads the page, and
this is an app people use with a half-typed transaction on screen in a shop.

The app checks for a new version on `visibilitychange`, so bringing it back to
the foreground is what finds an update — which on a phone is the only moment
that reliably happens, since an installed PWA is rarely "reloaded" at all.

## What is cached, and what is deliberately not

The service worker precaches the **app shell**: the JS, CSS, HTML and icons. So
the app opens instantly, opens offline, and opens on a flaky connection.

It caches **no data**. Every ledger read goes to Supabase: at launch, and again
when the app is returned to the foreground and what is on screen has had time to
go stale (`STALE_AFTER_MS` in `src/data/useLedger.ts`, five minutes). An
installed PWA survives for days without a reload, and the ledger is shared, so
"still open from yesterday" is the normal case rather than the odd one.

This is the one place the app trades convenience for correctness: a cached
balance is a balance that can be wrong without saying so, and "can I afford
this" answered from a stale envelope is worse than not answered at all. Offline,
the app opens and tells you it could not load rather than showing you figures it
is not sure about.

If offline entry is ever wanted, the shape is an outbox — queue writes locally,
replay on reconnect, and show unsynced entries as pending — not a read cache.
The domain layer is already pure and would not need to change; the seam is
`src/data/useLedger.ts`.

## iOS notes

- `.app-shell` takes `100svh` in a browser tab but `100vh` under
  `@media (display-mode: standalone)`. iOS misreports the dynamic units on a
  cold start, and a cold start is every launch there, since a backgrounded PWA
  is killed rather than suspended. Do not fold the two into a `max()` — that
  hands a tab the taller figure and reintroduces the rubber-band.
- `viewport-fit=cover` plus `env(safe-area-inset-*)` on the header and the
  bottom spacer. The app is drawn edge-to-edge whether or not it asks to be.
- Text inputs are Mantine's `md` size (16px). Anything smaller makes iOS zoom
  the page when a field takes focus.

## Icons

`public/favicon.svg` is the only hand-edited icon; the PNGs beside it are
generated by `npm run icons` and should never be edited directly. The SVG bleeds
its artwork to the edge of the box, which suits a browser tab; every other
surface rounds or masks the square, so the script re-lays the artwork inside
each output at its own coverage — 78% for the home-screen icons, 66% for the
maskable one, whose safe zone is a circle rather than a square.
